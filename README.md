# מערכת מכינת ניר עוז

מסמך זה נועד לייצר הכוונה ראשונית להמשך הפיתוח. תקרא אותו היטב ותיעזר בקלוד לכל שאלה. אני זמין לכל מה שצריך.

---

## מה קיים היום

מערכת הניהול השלמה של מכינת ניר עוז. רצה באוויר ובשימוש יומיומי.

**כתובת:** https://nirozmanager.vercel.app

**מה יש בה:**

- **נוכחות** — סימון יומי, לוח שנתי חודש-חודש, בקשות יציאה בשני
  שלבים (מדריך ממליץ, ראש מכינה מכריע), מכסות חופשה לכל מחצית
- **חניכים** — פרופיל מלא, תפקידים, מובילי שבוע, אירועים חריגים,
  ותיק שהצוות רואה
- **תורנויות** — גזרות ניקיון שבועיות, תורנות מטבח וחד״א יומית,
  טבלת מעקב עם ממוצעים והמלצות, וצ׳ק ליסט יומי
- **ניהול צוותים** — ועדות, סדרות וצוותים מזדמנים מנהלים בהם את
  המשימות שלהם, עם יו״ר ומעקב התקדמות
- **שיעורים** — גיליונות מרצים, גאנט שנתי, דירוגים וחוות דעת
- **ציוד** — מטבח (אוכל וחד״פ), מכולה וניקיון, מפתח מלאי ורשימות
  קניות, תקציב חודשי
- **בטיחות ותקלות** — דיווח פתוח לכל חניך, מעקב לאחראים
- **בוגרים, אירוח קבוצות, השאלת ציוד, מנות ותפריטים**
- **מחזורים** — פתיחת מחזור חדש מתוך האפליקציה, בלי דיפלוי
- **ניהול תוכן** — ראש המכינה עורך נהלים, תיאורי תפקידים והסברים
  בכל מסך, בלי מפתח

**הרשאות:** קוד אישי לכל איש צוות, שם משתמש וסיסמה לכל חניך,
וחשבון "צפייה בלבד" למי שרואה הכול ואינו משנה דבר.

## התחברות והתחלת עבודה

### 1. חשבון GitHub

צור חשבון ב-github.com ושלח לרועי את שם המשתמש. תקבל הזמנה למאגר במייל — אשר אותה.

### 2. מפתח SSH

כדי שתוכל לדחוף קוד, GitHub צריך לזהות את המחשב שלך. בטרמינל:

```bash
ssh-keygen -t ed25519 -C "your-name" -f ~/.ssh/id_ed25519 -N ""
```

לא יישאלו שאלות. נוצרו שני קבצים — פרטי שנשאר אצלך, וציבורי שמוסרים ל-GitHub.

הצג את הציבורי:

```bash
cat ~/.ssh/id_ed25519.pub
```

תודפס שורה אחת שמתחילה ב-`ssh-ed25519`. סמן אותה במלואה והעתק.

בדפדפן: https://github.com/settings/ssh/new

- **Title:** שם המחשב שלך
- **Key type:** Authentication Key
- **Key:** הדבק
- **Add SSH key**

המפתח הציבורי אינו סוד. הפרטי לעולם לא נשלח לאף אחד.

### 3. הורדת הקוד

```bash
cd ~/Desktop
git clone git@github.com:Bemaaleh-org/MechinaManager.git
cd MechinaManager
npm install
```

בפעם הראשונה תישאל `Are you sure you want to continue connecting?` — הקלד `yes` (מילה מלאה).

### 4. קובץ הסודות

צור קובץ בשם `.env` בשורש הפרויקט, עם שתי השורות שתקבל מרועי בערוץ פרטי:

```
MONDAY_TOKEN=...
SESSION_SECRET=...
```

⚠ **אסור להעלות את הקובץ הזה לגיט.** הוא חסום ב-`.gitignore` — אל תסיר אותו משם. אם סוד נכנס להיסטוריה בטעות, צריך להחליף את כל המפתחות של האפליקציה.

### 5. הרצה מקומית

```bash
npm run setup     # מאמת טוקן, לוחות, וזהות גיט
npm run dev
```

פתח את `http://localhost:5173` והתחבר עם הקוד שקיבלת.

## איך עובדים כאן

**הענף `main` הוא מה שרץ באוויר. אתה לא נוגע בו.**

הענף שלך הוא `lessons` והוא כבר קיים:

```bash
git checkout lessons
```

מכאן, בכל פעם שאתה רוצה לשמור:

```bash
git add -A
git commit -m "תיאור קצר של מה שנעשה"
git push
```

**מה קורה בזמן שאתה עובד:**

- האפליקציה ממשיכה לרוץ באוויר כרגיל, בלי השינויים שלך
- Vercel בונה לך **תצוגה מקדימה משלך** בכל דחיפה, בכתובת נפרדת. שם תראה את השינויים שלך בלי לגעת באפליקציה שרצה במטבח

**כשמשהו מוכן:**

תפתח Pull Request בגיטהאב מהענף `lessons` אל `main` — בקשה להוספת הקוד שלך לקוד הקיים. רועי יבדוק ויאשר, ורק אז השינוי יעלה לאוויר.

הדרישה לאישור לא חוסמת אותך — אתה ממשיך לעבוד על הדבר הבא בזמן שהבקשה ממתינה.

## ⚠ מגבלת Vercel — קרא לפני שאתה מוסיף קובץ ל-api/

**כל קובץ `.js` בתיקיית `api/` נספר כפונקציה. בתוכנית הנוכחית מותרות 12. כרגע תפוסות 6.**

זו לא המלצה סגנונית — זו מגבלה קשיחה. **חריגה ממנה שוברת את הדיפלוי של כל המערכת**, לא רק את התכונה שלך. האפליקציה במטבח לא תעלה.

**מה לא לעשות:**

```
api/equipment.js
api/reports.js
api/suppliers.js
api/orders.js
api/inventory.js
api/grades.js        ← 6 + 6 = 12. נגמר המקום.
```

**מה כן:**

```
api/lessons.js          ← נספר
api/_lessons-list.js    ← לא נספר
api/_lessons-create.js  ← לא נספר
api/_students.js        ← לא נספר
api/_attendance.js      ← לא נספר
```

**הכלל:** קובץ ששמו מתחיל בקו תחתון אינו נספר על ידי Vercel. הקובץ הראשי מנתב פנימית לפי פרמטר, למשל `/api/lessons?action=create`.

**זה הדפוס שכל האפליקציה בנויה עליו.** פתח את `api/attendance.js` או `api/kitchen.js` ותראה איך זה עובד — אין צורך להמציא כלום.

תכונה חדשה כמעט תמיד נכנסת כ-`?action=` בתחום קיים, לא כקובץ נספר חדש.

## עקרונות שאסור לשבור

### 1. monday היא מקור האמת

אין בסיס נתונים אחר. הכול חי בלוחות monday, והאפליקציה קוראת וכותבת אליהם בזמן ריצה.

**המשמעות בפועל:** מה שאפשר להגדיר בלוח — יוגדר בלוח, לא בקוד. מנהל המכינה צריך לשנות משימה, ניסוח או שיבוץ **בלי לכתוב קוד ובלי דיפלוי**.

זה עיקרון מנחה, לא המלצה. המערכת נבנתה סביבו במפורש.

### 2. הסודות לא בקוד

`MONDAY_TOKEN` ו-`SESSION_SECRET` נקראים ממשתני סביבה בלבד. **לעולם לא בקוד, לא בהערות, ולא בקומיט.**

מזהי הלוחות **כן** מקובעים בקוד, ב-`shared/`. הם אינם סוד — בלי טוקן אי אפשר לגשת אליהם.

### 3. האימות בשרת, לא בלקוח

כל נקודות הקצה עטופות ב-`withAuth`. השרת קובע מי המשתמש לפי העוגייה, ולא לפי מה שהדפדפן מצהיר.

**כשתוסיף נקודת קצה — היא חייבת להיות מאומתת.** בדיקת תפקיד בצד הלקוח היא נוחות בלבד, לא הגנה.

### 4. נתון רגיש מסונן בשרת

**הסינון בשרת** — הנתון לא יוצא החוצה, לא רק מוסתר בתצוגה. הסינון בנוי כמיפוי
מפורש שדה-שדה, כדי שעמודה חדשה בלוח לא תזלוג בטעות.

אין כרגע מחירים במערכת, אבל קוד הכניסה כן — והוא לעולם לא יוצא מהשרת, גם לא
למנהל. שמור על הדפוס בכל נקודת קצה חדשה שמחזירה שורות משתמשים או עלויות.

### 5. אין מעקב אישי על עבודת התורנים

לוח המשימות השבועי הוסר, אבל ההתחייבות שמאחוריו לא בוטלה: **לא מי סימן ולא
מתי.** זו התחייבות שניתנה לחניכים, לא החלטה טכנית. אל תוסיף שדה שמזהה מי ביצע
מה, גם אם זה נראה שימושי. ועדיף לשמור על פשטות ולא להעמיס עוד שדות ופעולות.

### 6. כשל טעינה נראה אחרת מ"אין נתונים"

היה באג שחי יומיים: הקטלוג חזר ריק בייצור, והמסך נראה בדיוק כמו מטבח ריק.

היום `storage.js` מסמן `loadFailed` ומוצג באנר אדום. **שמור על העיקרון בכל קוד חדש** — משתמש חייב לדעת שהחיבור נכשל, ולא לחשוב שהמלאי אזל.

### 7. כל הקריאות לשרת דרך `src/api.js`

זו הדלת היחידה. **אל תכתוב `fetch` ישירות בשום מקום אחר.**

הבאג מסעיף 6 נגרם בדיוק מזה — קובץ אחד עקף את הכלל ונשאר עם כתובות ישנות.

## לוחות monday

| לוח | תפקיד |
|---|---|
| מטבח – ציוד | אוכל וחד״פ: כמות, סוג, מפתח |
| מטבח – קניות | רשימת הקניות של המטבח |
| ציוד מכולה · קניות מכולה | מכולה וניקיון |
| מצבת חניכים | החניכים, מגדר, מוביל |
| לוח שנה · היעדרויות · בקשות | נוכחות ויציאות |
| גיליונות · מפגשים · דירוגים | שיעורים |
| משתמשים והרשאות | קודי כניסה ורשימת חניכים |

המזהים ושמות העמודות נמצאים ב-`shared/`.

### על מנגנון הציוד

שני תחומי הציוד — המטבח (אוכל · חד״פ) וציוד המכינה (מכולה · ניקיון) — הם
אותה טבלה בדיוק, ולכן הם חולקים **מסך אחד** ב-`src/Equipment.jsx`. כל תחום
מספק אובייקט הגדרה: הניסוחים שלו ושבע קריאות השרת שלו.

שני עותקים של מסך כזה היו נפרדים זה מזה בתיקון הראשון שנעשה רק באחד מהם.

**המפתח** — כמה צריך להיות מכל פריט — נשמר בלוח ולא בקוד, כי המכינה משנה
אותו מדי חודש. מה שחסר ביחס אליו הופך לרשימת קניות בלחיצה אחת.

⚠ **הכמות היא עמודת טקסט ולא מספר**, בכוונה: ברשימת המקור יש כמויות כמו
"40 חבילות של 10" ו-"2 קופסאות קילו כמעט מלאות". עמודת מספר הייתה מוחקת את
התיאור. חישוב החוסרים קורא את המספר הראשון — ראו `shared/par.js`.

תשובות אמיתיות מול monday האמיתית — לא mock ולא סימולציה.




⚠ **כל חבילה יוצרת את הנתונים שלה ומוחקת אותם לפי מזהה**, בכל

בגלל ניקוי שסינן לפי ערך, וחבילה אחת השאירה שלושה ימי נוכחות
בלוח האמיתי כי ספרה לוח אחד מתוך שניים.

⚠ **הן דורשות `.env` מלא** ורצות מול monday של המכינה. אין
סביבת בדיקה נפרדת.

⚠ **`npx vite build` אינו תופס `ReferenceError`** — משתנה
שנקרא בלי ייבוא עובר את הבנייה ונופל רק בזמן ריצה. זה קרה
כאן פעמיים. הבדיקות הן מה שתופס את זה.


### `tools/api-snapshot.mjs`

מצלם את התשובות של כל נקודות הקצה — כתורן, כמנהל, ובלי התחברות.

```bash
node --env-file=.env tools/api-snapshot.mjs /tmp/after.txt
diff tools/snapshot-before-dev.txt /tmp/after.txt
```

**השתמש בו לפני ואחרי כל שינוי בשכבת השרת.** הוא תפס תקלות שאף בדיקה ידנית לא הייתה מגלה.

שים לב: הוא מתעד **מבנה**, לא ערכים. "אפס הפרשים" אומר שלא שברת כלום — לא שהשינוי שלך עובד. את זה בדוק בנפרד.

### פרמטר `?date=`

בפיתוח בלבד: `localhost:5173/?date=2026-08-13` גורם למסך להתנהג כאילו זה התאריך הזה. שימושי לבדיקת ימים אחרים ושבועות עתידיים.

**בייצור הוא חסום לחלוטין** — בשרת, לא בלקוח. אל תסיר את ההגבלה.

### גלישה בסתר

`localStorage` מסתיר באגים — זה מה שהסתיר את הבאג מסעיף 6 במשך יומיים. **בדוק תמיד בחלון פרטי** לפני שאתה מסיק שמשהו עובד.

## סיכום

1. עובד בענף `lessons`. `main` לא שלך.
2. מה שאפשר להגדיר ב-monday — מגדירים ב-monday, לא בקוד.
3. כל נקודת קצה חדשה מאומתת בשרת.
4. נתון רגיש מסונן בשרת.
5. אין מעקב אישי על משימות.
6. לא מוסיפים קבצים ל-`api/` בלי לספור — המגבלה 12, תפוסות 6.
7. כל קריאה לשרת דרך `src/api.js`.
8. בודקים בגלישה בסתר.
